# 重量·容量换算站（Weight-Volume）设计稿

> 日期：2026-10-06　状态：**待用户确认**　灵感来源：[data-Calculation](https://fjkkx77.github.io/data-Calculation/)
> 确认后进入实施计划；实施前所有「待核实」数值都要先查到一手出处。

---

## 1. 目标

做一个手机优先的网页，解决两件事：

1. **换算**：斤、两、克、千克、毫升、升等重量和容量单位互相换算，包括按物质在重量和容量之间换算。
2. **好记**：把抽象的数字翻译成生活里的常见物品（一个鸡蛋 ≈ 一两，一瓶矿泉水 ≈ 一斤），帮助建立量感。

**成功判据**

- 任意单位输入一个数，其他单位马上给出正确结果，所有定义值都有一手出处。
- 输入的数能自动翻译成「≈ N 个某物品」，而且挑出来的物品要好记。
- 在 320 / 390 / 430 宽度的手机上都能完整显示，没有横向滚动。

**不做的事（YAGNI）**

- 不做账号、同步、历史记录。
- 不用真实照片，物品图用系统 Emoji。
- 不做温度、长度等其他物理量。

- `index.html` 只负责展示和交互。

## 4. 数据设计（`data.js`）

### 4.1 单位

每个单位记录：`id`、`name`（显示名）、`group`（分组）、`kind`（`mass` 重量 / `volume` 容量）、`toBase`（换成基准单位的系数；重量的基准是克，容量的基准是毫升）、`exact`（是否定义值）、`source`。

| 分组 | 单位 | 备注 |
|---|---|---|
| 市制 | 斤、两、钱、公斤 | 1 斤 = 500 克 = 10 两，1 两 = 10 钱（**待核实出处**：国务院统一计量制度的相关文件） |
| 公制重量 | 克、千克、吨 | SI |
| 公制容量 | 毫升、升、立方厘米、立方米 | 1 毫升 = 1 立方厘米 |
| 厨房量具 | 茶匙、汤匙、杯 | **杯要分开列中式/公制/美制**；中式汤匙、茶匙的取值要查证，没有统一标准就明说并注明取值依据 |
| 英美 | 磅、盎司、美制液量盎司、英制液量盎司、美制加仑、英制加仑 | 磅、盎司以国际码磅协定（1959）为准；加仑和液量盎司以 NIST 等一手出处为准（**全部待核实**） |
| 旧制/港台 | 旧制斤两（16 两制）、台斤、港斤 | **全部待核实**：旧制 1 斤 = 16 两（「半斤八两」）对应的克数、台斤的克数、港斤（司马斤）的克数 |

### 4.2 物质密度

记录：`id`、`emoji`、`name`、`density`（克/毫升，典型值）、`range`（范围，可选）、`level`（`physical`）、`source`、`note`。

- 默认物质：💧 水，取 1 克/毫升（常温下的工程近似，注明这一点）。
- 牛奶、食用油：给出典型值和出处。
- **大米、面粉、白糖这类粉粒状物质**：密度受装填松紧影响很大，**必须给范围并在界面上说明**，不能给出看起来很精确的单一数值。

### 4.3 物品

记录：`id`、`emoji`、`name`、`kind`（`mass`/`volume`）、`value`（典型值，克或毫升）、`range`（可选）、`level`（`standard` 有标准 / `measured` 有权威数据 / `estimate` 经验值）、`source`、`linkable`（能否参与「≈ N 个」联动推荐）。

**挑选原则**：生活里随手能拿到、个头差不多固定。个头差别很大的物品（比如西瓜）只进图鉴、展示范围，`linkable = false`。

候选清单（**数值全部待核实**，实施时逐条查出处）：一枚 1 元硬币、一张 A4 纸、一个鸡蛋、一个苹果、一部手机、一瓶 550 毫升矿泉水、一罐可乐、一盒牛奶、一袋 5 公斤大米、一个西瓜（仅图鉴）、一桶食用油等。

### 4.4 口诀

记录：`text`、`detail`、`source`。初定的几条：一斤 = 十两 = 500 克；1 升水 ≈ 2 斤；「半斤八两」的来历（旧制 16 两）。

### 4.5 数据可信度三级

| 级别 | 含义 | 界面标注 |
|---|---|---|
| 定义值 | 法规或协议直接规定，精确 | 不加「约」 |
| 物理值/标准值 | 有权威来源但存在自然误差 | 「约」+ 范围 |
| 经验值 | 找不到权威来源，按常见规格估算 | 「约」+ 明确标出「经验值」 |

**硬规则**：每条数据都必须有 `source`，空的不让上线（由测试拦截）。

## 5. 计算设计（`convert.js`）

| 函数 | 作用 |
|---|---|
| `toBase(value, unitId)` / `fromBase(base, unitId)` | 单位和基准单位（克/毫升）互换 |
| `convertAll(value, unitId, substanceId)` | 返回所有单位的结果；跨重量和容量时用所选物质的密度 |
| `formatNumber(x)` | 按有效数字显示，去掉浮点尾巴，很大或很小的数自动调整位数 |
| `formatJinLiang(grams, system)` | 组合写法：市制「1 斤 2 两 5 钱」/ 旧制 16 两制 |
| `suggestItems(base, kind)` | 从 `linkable` 物品里挑 2–3 个最好记的，返回「≈ N 个」 |

**联动推荐规则**（初定参数，实施时用真实数据调，调整理由写进注释）：

- 倍数要落在一个好记的区间里（比如 0.5 到 20），不出现「≈ 0.037 个」或「≈ 3000 个」。
- 优先选接近整数或接近 0.5 的倍数。
- 同一次推荐里，物品的量级要拉开，避免三个都是差不多大的东西。

**精度**：中间计算一律用基准单位，只在最后显示时取整，不在单位之间来回换算。

## 7. 异常与边界

| 情况 | 处理 |
|---|---|
| 输入为空、负数、非数字 | 空 = 清空其他格；负数不接受；非数字忽略 |
| 极大或极小的数 | `formatNumber` 自动调整位数，不撑破格子 |
| 没有合适的物品可推荐 | 不显示联动标签，不硬凑 |
| 粉粒状物质跨类换算 | 结果前加「约」并提示误差来源 |
| Emoji 在某些设备上显示不出来 | 名称文字始终显示，Emoji 只是辅助 |

## 14. 每行从小到大（2026-10-07，同日第四轮）

**用户原话**：「我想让这些所有的单位每一行都按左边最小到右边最大的依次递增的排列方式排列……便于我查看」。
